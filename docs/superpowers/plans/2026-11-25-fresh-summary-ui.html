목표: 기존 발행 기사를 보존하고 새 소식 카드 최대 10개의 요약 요청과 상태를 표시한다. 앱 모듈·모의 API/DOM 테스트 계획은 coordinator가 승인했으며 템플릿과 생성 HTML은 TSM 담당이다.

TSM 신규 카드 → briefing:fresh-rendered → DOM 후보 중복 제거 → 최대 10개 POST → 30초 상태 GET → 신규 카드 갱신
  1. 완료: 계약 경계 테스트를 먼저 작성하고 미구현 실패 확인
  2. 완료: 중복 방지·10개 제한·구 API 호환·숨김/종결 중단·시각/예산 검증·textContent 렌더 구현
  3. 완료: 동일 DOM 계약의 모의 화면을 Orca 브라우저로 검증
  4. 진행: 전체 Node 테스트, 확정 API 대조, PR 준비

DOM: .fresh .item[data-candidate-id], 선택 data-summary-status; document 이벤트 briefing:fresh-rendered, detail {updated: d.updated}; module src=/briefing/fresh-summary.js. 리스너 등록 후 기존 DOM 검사.

확정 API v1 summary: title_ko·background·key(문자열 배열)·detail·implication·has_body(논리값). 상태 GET도 최대 10개씩 분할. 중복 링크는 유효 날짜의 /briefing/YYYY-MM-DD#kr|global|notice:부문:기사 내부 경로만 허용하며 cache:·fresh:는 문구로만 표시.

검증: 신규 23개 및 전체 57개 Node 테스트 성공, 문법 검사 성공, 로컬 대기→완료·정적 보존·390px 화면 확인. 기존 사이트 검증 실패: 수정하지 않은 루트 index.html의 theme-color·noscript 누락 2건.

parent 편집·실운영 요약·유료 호출·배포 금지. 예산 90분, 계약 보완 최대 2회.

미배포 호환: 404·405·501, HTML fallback, 미지원 status는 페이지 재열기 전까지 조용히 비활성화한다. POST·polling·오인 대기 표시를 제거하고 원문 목록과 이미 완료한 요약을 보존한다. 로컬 404 후 10회 재클릭: 최초 요청 1회·추가 요청 0회·요약 블록 0개.
