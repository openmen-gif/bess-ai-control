미배포 호환: 404·405·501, HTML fallback은 페이지 재열기 전까지 조용히 비활성화한다. POST·polling·오인 대기 표시를 제거하고 원문 목록과 이미 완료한 요약을 보존한다. 로컬 404 후 10회 재클릭: 최초 요청 1회·추가 요청 0회·요약 블록 0개.

독립 검토 보완: GET 연속 실패는 30→60→120→240→300초 백오프(최대 5분), 정상 복구 시 오류 안내 초기화; 긴 Retry-After deadline은 보존하며 최대 1시간 타이머 chunk로 대기; 과거 HTTP-date·0초는 최소 30초 재요청 억제; 미수락 POST429는 재요청 안내만 표시; ISO 소수초 1~9자리와 엄격한 달력 검증; GET의 생략 선택 필드 next_retry_at·duplicate_of·summary 초기화. failed/over_budget 초기 GET 1회는 최신 예산·결과 확인에 필요하므로 유지하며 종결 후 polling 0회. limit30은 승인 정책으로 유지.

승인된 v1.1: data-summary-requested 문자열 false는 신규 POST, true는 기존 결과 조회, 누락은 v0 유지, 잘못된 값은 해당 카드만 제외한다. 이벤트 detail.summary_available이 boolean false일 때만 document 단위 latch로 비활성화하며 이후 true나 destroy/재초기화도 같은 페이지에서는 재개하지 않는다(새 페이지 필요). 진행 중 응답도 비활성화 이후 추가 GET을 만들지 않는다. 전체 예산30과 요청429를 구분한다. 실제 SCRIPT 통합 fixture는 운영 49aa0e9fcf250f7a2d8aaa62442de40d4d23b857를 AST 상수 추출로 그대로 삽입한 기준 재현본: 신규4카드·POST0·상태GET1·requested속성없음4개, 정적본문 및 정적재시도상태 공존 확인; 운영 수정 SHA로 재생성하기 전 통합 성공으로 판정하지 않는다. 생성 명령: py -3.14 scripts/build-briefing-integration-fixture.py --publisher <운영 파일의 조회 사본> --commit <고정 40자리 SHA>. v1.2 확정: unknown·미지 기사 status는 기사별 종결, 403은 신규 POST만 document 단위 차단하며 기존 작업 GET은 유지한다. IP5/배치10 수락 방식은 운영 코드 대조 대기다.

v1.2 회귀: 최소 unknown 객체에 attempts/updated_at를 요구하지 않고 해당 기사만 종결한다. 미지 문자열 status도 기사별 처리하고 정상 기사·이미 완료한 요약을 보존한다. 같은 DOM 이벤트는 unknown을 재요청하지 않으며 새로 발급한 DOM의 requested=false에서만 수동 재요청한다. 403은 신규 POST만 같은 document에서 차단하고 신규 카드/재클릭에도 반복하지 않으며 기존 작업 GET은 유지한다. 400은 요청 확인 실패라는 중립 문구를 사용한다. 로컬 403 후 10회 재클릭도 최초 POST1회·원문 보존을 확인했다. 배치10과 IP KST일 고유id5는 별도 한도이며 전체/부분 수락은 운영 수정 SHA 확인 전 단정하지 않는다.
